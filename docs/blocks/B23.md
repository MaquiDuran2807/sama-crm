# Block B23 — Fix Timeline Chart: Date Grouping & Stage Filtering

## User Story

Como usuario del CRM, quiero que el gráfico "Leads en el tiempo" muestre correctamente los datos agrupados por día, semana, mes o trimestre según el rango de fechas seleccionado, y poder filtrar las líneas del gráfico por etapa del pipeline sin perder mi selección al cambiar el período.

---

## Root Causes Found

### 1. Fragile view mode detection
El código usaba `isMonthlyView = dayData.length > 45` para decidir si agrupar por mes o por día. Este threshold era arbitrario y no correspondía al filtro de días del usuario:
- Si el usuario seleccionaba "Todo" (days=0, podría tener 200+ días), `dayData.length > 45` era `true` → grouping mensual, correcto.
- Si había menos de 45 días de datos, `dayData.length <= 45` → grouping diario, también correcto por coincidencia.
- El problema: cuando se cambiaba a "Trimestre" (90 días), `dayData.length` podría seguir siendo <= 45 si no había datos, y el código agrupaba por día en vez de por semana.

### 2. Stage name mismatch en `leads_by_stage`
El backend construye `leads_by_stage` iterando sobre `pipeline_stages`, usando `stage["name"]` como key. El frontend recibía `stageData` (que es `leads_by_stage`) y también iteraba sobre `pipelineStages` para obtener los nombres. Aunque ambos usaban el mismo array `pipelineStages`, el orden y la verificación dependían de coincidencias de string sensibles a acentos y mayúsculas.

Además, había inconsistencia en nombres de etapas en `stageColors`:
- El backend usa "Cotizacion Enviada" (sin tilde)
- `stageColors` tenía "Cotización Enviada" (con tilde) como key

### 3. Phase selector se reseteaba al cambiar fecha
Cuando `fetchAnalytics()` era llamado (al cambiar el filtro de fechas), `renderPhaseSelector()` re-creaba todos los pills reseteando `selectedPhases` a un nuevo Set con todos los stages seleccionados. El usuario perdía su selección de etapas al cambiar de período.

### 4. Alineación de fechas incompleta para grouping semanal
No había soporte real para grouping semanal. La lógica solo distinguía entre "daily" y "monthly" basándose en `dayData.length`.

---

## Fixes Applied

### Step 1: Nueva función `getViewMode(days)`
Reemplaza `isMonthlyView = dayData.length > 45` con lógica basada en el filtro del usuario:

```javascript
function getViewMode(days) {
    if (days === 0) return 'monthly';
    if (days <= 30) return 'daily';
    if (days <= 90) return 'weekly';
    if (days <= 365) return 'monthly';
    return 'quarterly';
}
```

### Step 2: Función `groupDataByPeriod(dataArray, viewMode)`
Reorganiza todos los datasets (new, won, lost, quotes) según el `viewMode`:

| viewMode   | Agrupación | Ejemplo labels |
|------------|------------|----------------|
| daily      | Por día    | `10 Abr`, `11 Abr` |
| weekly     | Por semana ISO | `S15 Abr`, `S16 May` |
| monthly    | Por mes    | `Feb 2026`, `Mar 2026` |
| quarterly  | Por trimestre | `Q1 2026`, `Q2 2026` |

### Step 3: Función `buildStageDataMap(stageData, stageName, viewMode)`
Aplica el mismo grouping por período a los datos de cada etapa del pipeline (Lead, Calificación, etc.) para que las líneas del chart se alineen correctamente con los labels del eje X.

### Step 4: Preservación de selección de fases
En `fetchAnalytics()`, antes de llamar `renderPhaseSelector()` (que resetea `selectedPhases`), se guarda la selección actual en un objeto `previousSelection`:

```javascript
var previousSelection = {};
selectedPhases.forEach(function(v) { previousSelection[v] = true; });

renderPhaseSelector();  // resetea selectedPhases a todos activos

// Restaurar selección previa
var stageNames = pipelineStages.map(function(s) { return s.name || s; });
stageNames.forEach(function(name) {
    if (previousSelection.hasOwnProperty(name)) {
        selectedPhases.add(name);
    }
});
```

### Step 5: Consistencia de nombres en `stageColors`
Se added both "Cotizacion Enviada" (sin tilde) y "Cotización Enviada" (con tilde) como keys en `stageColors`.

## How to Test Manually

1. **Agrupación por día (7d, 30d):**
   - Abrir `/crm/codensolar/analytics/`
   - Seleccionar "Semana" (7d) → verificar que el eje X muestre labels tipo `10 May`
   - Seleccionar "Mes" (30d) → verificar que el eje X muestre labels tipo `11 May`
   - El chart debe mostrar puntos de datos por día

2. **Agrupación por semana (90d):**
   - Seleccionar "Trimestre" (90d) → verificar que el eje X muestre labels tipo `S20 May`
   - Cada punto representa una semana ISO

3. **Agrupación por mes (365d, Todo):**
   - Seleccionar "Año" (365d) → verificar que el eje X muestre labels tipo `Ene 2026`
   - Seleccionar "Todo" → verificar grouping mensual o trimestral

4. **Filtrado por etapa:**
   - Con cualquier período activo, hacer click en un pill (ej: "Cerrado Ganado")
   - La línea correspondiente desaparece del chart
   - Cambiar el período (ej: de "Mes" a "Trimestre")
   - El chart se redibuja con grouping diferente pero "Cerrado Ganado" sigue oculto
   - Hacer click en el mismo pill nuevamente → la línea reaparece

5. **No deseleccionar la última fase:**
   - Deseleccionar todas las fases menos una
   - Intentar deseleccionar la última → el click no tiene efecto, el pill permanece activo

6. **Verificar que otros charts no se rompen:**
   - Embudo de ventas → debe seguir mostrando datos
   - Mix de fuentes → debe seguir mostrando datos
   - Mapa SVG de Colombia → debe seguir mostrando datos
   - Tarjetas de stats → deben seguir mostrando números

## Known Limitations

- El grouping semanal usa semanas ISO (lunes como primer día). Esto puede diferir de la definición de "semana" que ожидать el usuario si esperan semanas comenzando en domingo.
- Para períodos "Todo" (days=0), se fuerza grouping mensual porque no hay un rango definido. El usuario no puede forzar grouping diario para datos históricos completos.
- Los colores de las etapas del pipeline están hardcodeados en `stageColors`. Si el backend provee colores personalizados en `pipeline_stages[i].color`, estos se usan en los pills pero no en las líneas del chart para etapas dinámicas.
- La función `getWeekNumber` usa la convención ISO que puede producir semanas 52/53 al final de algunos años.
