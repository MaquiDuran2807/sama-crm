# Block 14: Pipeline configuration page — HU-13

**Fecha:** Mayo 2026

## User Story implementada

### HU-13: Configuración del pipeline de ventas

User Story: As a CRM user, I want to customize my sales pipeline (rename stages, change colors, reorder, add or remove stages) from a visual interface, so that the pipeline reflects exactly how my business operates.

## Archivos modificados/creados

- `tenants/interfaces/views.py` — acción `pipeline_config_update` (GET + PATCH) en `TenantViewSet`
- `crm/interfaces/views.py` — clase `PipelineConfigView` para renderizar la página HTML
- `crm/web_urls.py` — ruta `/crm/<tenant>/config/` → `PipelineConfigView`
- `crm/templates/crm/pipeline_config.html` — plantilla completa con SortableJS y toda la UI
- `crm/templates/crm/base.html` — enlace "Configuración" en el dropdown de usuario (antes disabled, ahora funcional)
- `tenants/tests/test_views.py` — tests para PATCH pipeline, GET pipeline, validación de nombre vacío, validación de stages faltante
- `crm/tests/test_views.py` — tests para la página de configuración (200, contexto de stages, login requerido)
- `docs/blocks/B14.md` — este archivo

## Decisiones clave

- El endpoint de actualización usa `pipeline-config` (no `pipeline`) para evitar colisión con la acción GET existente que mapea a `pipeline/`.
- `TenantViewSet` cambiado de `ReadOnlyModelViewSet` a `ModelViewSet` para permitir PATCH. El queryset de solo lectura se mantiene, solo se habilita el método `patch`.
- La plantilla es autocontenida: CSS inline con variables de tema, JS inline con SortableJS via CDN.
- Inline editing: doble-click en el nombre de etapa lo convierte en input, Enter o blur guarda.
- Delete deshabilitado si solo queda 1 etapa (protección mínima contra pipeline vacío).
- El color picker usa `<input type="color">` native con overlay transparente para mejor UX.
- El save solo llama a la API cuando el usuario hace click en "Guardar cambios" (no en cada edición).

## Endpoint API

### `GET /api/tenants/{slug}/pipeline-config/`
Retorna el pipeline actual (mismo formato que `/pipeline/`).

### `PATCH /api/tenants/{slug}/pipeline-config/`
**Body:**
```json
{
  "stages": [
    {"name": "Nuevo Lead", "color": "#003366", "order": 1},
    {"name": "Contactado", "color": "#FF9933", "order": 2}
  ]
}
```
**Respuesta 200:**
```json
{
  "stages": [...],
  "allow_skip_stages": true
}
```
**Errores:**
- 400 si falta el array `stages` o alguna etapa no tiene nombre.

## Componentes UI

1. **Lista ordenada de etapas** — cada item tiene: handle de arrastre, color picker circular, nombre editable (doble-click), número de orden, botón eliminar.
2. **SortableJS** — permite arrastrar y soltar para reordenar. Actualiza el array de etapas en memoria.
3. **Color picker** — círculo que muestra el color actual, al click abre el input nativo tipo color.
4. **Inline editing** — doble-click en nombre → input, Enter/blur → guarda.
5. **Botón eliminar** — deshabilitado cuando hay 1 sola etapa.
6. **"Añadir etapa"** — agrega nueva etapa con nombre por defecto y color rotativo.
7. **Toast de éxito/error** — notificación inferior derecha tras guardar.
8. **Botón "Guardar cambios"** — prominente al final de la página.

## Cómo verificar

1. Ir a `/crm/<tenant>/config/` → aparecen las etapas del pipeline configuradas.
2. Arrastrar una etapa a otra posición → se reordena visualmente.
3. Doble-click en nombre → editar inline, Enter para guardar.
4. Click en el círculo de color → seleccionar nuevo color.
5. Click en papelera → etapa desaparece (si hay más de 1).
6. Click "Añadir etapa" → nueva etapa al final, se abre para edición.
7. Click "Guardar cambios" → toast de éxito, dashboard refleja los cambios.
8. Ir al dashboard → el Kanban muestra las nuevas etapas, colores y orden.

## Limitaciones conocidas

- Si se elimina una etapa que contiene leads, esos leads siguen teniendo el nombre de etapa antiguo en `current_stage`. Aparecen en el Kanban bajo una columna "huérfana" que no está en el pipeline. Para MVP esto es aceptable.
- No hay validación de colores (cualquier valor hex es aceptado).
- El endpoint PATCH no valida duplicados en nombres de etapa.
- No hayundo después de guardar (pero se puede volver a editar y guardar).
- La página no es accesible para usuarios no autenticados (LoginRequiredMixin).

## Compatibilidad

- Dashboard Kanban: regenera las columnas automáticamente al recargar, respetando colores y orden del `pipeline_config.stages`.
- Analytics: el funnel se ordena por `order` del pipeline, si cambia el orden las analíticas también.
- No rompe: drag & drop, nota modals, stage change, IA summary, theme toggle, trash, lead detail.
