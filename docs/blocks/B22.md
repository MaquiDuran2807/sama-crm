# Bloque B22 — Selector de fases en el grafico de tendencias

## Historia de usuario

Como vendedor quiero **filtrar el grafico de tendencias por fase del pipeline** (Lead, Calificacion, Cotizacion Enviada, Seguimiento, Cerrado Ganado, Cerrado Perdido) para analizar tendencias especificas de cada etapa. Por defecto se muestran las 4 series clasicas (Leads nuevos, Cerrados Ganados, Cerrados Perdidos, Cotizaciones Enviadas), y el usuario puede activar o desactivar cualquier fase adicional del pipeline.

---

## Arquitectura

### Flujo de datos

```
Backend (views.py)
  leads_by_stage: dict[fase] → [{"date": "2025-01-15", "count": 3}]
  pipeline_stages: [{"name": "Lead", "color": "#003366", "order": 1}, ...]
  leads_by_day: nuevos leads por fecha
  leads_by_stage_won: leads cerrados ganados por fecha
  leads_by_stage_lost: leads cerrados perdidos por fecha
  quotes_sent: leads en etapa Cotizacion Enviada

fetchAnalytics()
  └─ renderPhaseSelector()
        Crea <button class="phase-pill"> para cada fase del pipeline.
        Inicializa selectedPhases (Set global) con las 4 fases por defecto.
  └─ renderTimeChart()
        Construye datasets[] con los 4 datos clasicos + fases adicionales.
        Guarda todos los datasets en timelineAllDatasets (copia).
        Muestra solo los datasets cuyas labels estan en selectedPhases.

togglePhase(pill, name)
  Agrega o elimina la fase de selectedPhases.
  Llama updateTimelineChart().

updateTimelineChart()
  Filtra timelineAllDatasets por selectedPhases.
  Actualiza charts.timeline.data.datasets y llama chart.update().
```

### Selector de fases (pills)

Cada fase del pipeline se renderiza como un `<button class="phase-pill">`:

- **Activo:** borde del color de la fase, texto del color de la fase, fondo semi-transparente (`color + '22'`).
- **Inactivo:** borde gris, texto gris.
- **No se puede deseleccionar el ultimo:** `togglePhase` retorna early si `selectedPhases.size <= 1`.

## Campos en la API

### Endpoint
`GET /api/crm/tenants/{slug}/analytics/?days=&source=`

### Estructura de los campos nuevos

```json
{
  "leads_by_stage": {
    "Lead": [{"date": "2025-01-01", "count": 5}, ...],
    "Calificacion": [{"date": "2025-01-01", "count": 3}, ...],
    "Cotizacion Enviada": [{"date": "2025-01-01", "count": 2}, ...],
    "Seguimiento": [{"date": "2025-01-01", "count": 1}, ...]
  },
  "pipeline_stages": [
    {"name": "Lead", "color": "#003366", "order": 1},
    {"name": "Calificacion", "color": "#FF9933", "order": 2},
    {"name": "Cotizacion Enviada", "color": "#FF6600", "order": 3},
    {"name": "Seguimiento", "color": "#FFCC00", "order": 4},
    {"name": "Cerrado Ganado", "color": "#00CC66", "order": 5},
    {"name": "Cerrado Perdido", "color": "#FF3333", "order": 6}
  ]
}
```

### Logica de calculo (backend, views.py)

1. Se cuentan leads por fecha y etapa: `leads_qs.extra(select={"day": "DATE(created_at)"}).values("day", "current_stage").annotate(count=Count("id"))`.
2. Se agrupan por fecha: `stage_by_date[day][stage] = count`.
3. Se arma el dict `leads_by_stage` con una entrada por cada fase del pipeline.
4. Se retorna `pipeline_stages` para que el frontend conozca los nombres y colores.

## Bugs corregidos

### Bug 1: Chart desaparecia al togglear

**Sintoma:** Al hacer click en cualquier pill, todo el grafico de tendencia desaparecia.

**Causa raizal:** `selectedPhases` se reseteaba a `new Set()` dentro de `renderPhaseSelector()` ANTES de que `renderTimeChart()` creara el chart. En la primera carga funcionaba porque `renderPhaseSelector()` se ejecutaba primero, pero `renderTimeChart()` destruia y recreaba el chart en cada `fetchAnalytics()`.

Cuando el chart se reconstruia, `timelineAllDatasets` se llenaba con los nuevos datos, pero `updateTimelineChart()` buscaba en un Set `selectedPhases` que no contenia las labels de los nuevos datasets.

**Correccion:**
1. `renderPhaseSelector()` ahora se ejecuta ANTES de `renderTimeChart()` en `fetchAnalytics()`, garantizando que `selectedPhases` esta poblado antes de la creacion del chart.
2. `updateTimelineChart()` ahora incluye guardas con `console.log` para depuracion y usa `selectedPhases.size > 0` con `timelineAllDatasets.slice()` para evitar mutacion de la copia original.

### Bug 2: Expresion `%` dentro de string template en Node.js

**Sintoma:** Error de sintaxis `"missing ) after argument list"` en Node.js al compilar el JS.

**Causa raizal:** La expresion `Object.keys(stageColors).indexOf(stageName) % 8` dentro de un string `hsl()` era parseada incorrectamente por V8. La sub-expresion `% 8` se interpretata como operador modulo fuera de contexto.

**Correccion:** Se envolvio en parentesis: `(Object.keys(stageColors).indexOf(stageName) % 8)`.

### Bug 3: Funciones duplicadas

**Sintoma:** El archivo `analytics.js` contenia DOS definiciones de `renderPhaseSelector` (la correcta + una copia corrupta con codigo del chart de timeline). Esto causaba que `renderPhaseSelector` nunca se ejecutara correctamente.

**Correccion:** Se eliminaron las lineas duplicadas, dejando solo la definicion correcta.

## Como probar manualmente

1. **Poblar datos de prueba:**
   ```bash
   python manage.py seed_dynamic
   ```

2. **Abrir analiticas:**
   ```
   http://localhost:8000/crm/codensolar/analytics/
   ```

3. **Verificar el selector de fases:**
   - Debajo de "Leads en el tiempo" debe aparecer una fila de pills con las fases del pipeline.
   - Por defecto, los 4 primeros deben estar activos (coloridos).
   - Al hacer click en una fase adicional (e.g. "Calificacion"), la linea aparece en el grafico.
   - Al deseleccionar una fase, la linea desaparece del grafico.
   - No se puede deseleccionar la ultima fase activa (el click no hace nada).
   - Al cambiar el periodo (semana/mes/trimestre), las fases se resetean a los 4 valores por defecto.

4. **Verificar en consola del navegador:**
   ```
   [updateTimelineChart] selectedPhases size: 4 chart: true allDatasets: 4
   [updateTimelineChart] showing 3 datasets of 4
   ```

5. **Probar en ambos temas:** Cambiar entre oscuro y claro. El grafico se reconstruye y las fases visibles se mantienen.

## Limitaciones conocidas

- **Solo fases del periodo:** Si una fase no tiene datos en el rango de fechas seleccionado, su pill aparece pero el dataset esta vacio. El grafico no muestra linea para esa fase.
- **Sin persistencia:** Las selecciones de fases NO se guardan entre sesiones o recargas de pagina. Al recargar se resetean a los 4 valores por defecto.
- **Maximo 12 fases visibles:** Si el pipeline tiene mas de 12 fases, todas se renderizan pero el chart puede verse saturado.
- **Datasources limitados:** Los 4 datasets clasicos usan campos especificos (`leads_by_day`, `leads_by_stage_won`, `leads_by_stage_lost`, `quotes_sent`). Las fases adicionales usan `leads_by_stage`. Si el backend no retorna una fase en ninguno de estos campos, no se mostrara.
