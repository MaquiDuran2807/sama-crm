# Bloque B19 — Mapa SVG de Colombia por departamento (reemplaza Leaflet heatmap)

## Historia de usuario

Como vendedor quiero visualizar en el dashboard de analíticas un **mapa de Colombia por departamento** que se coloree según la densidad de leads, para enfocar mis esfuerzos en las zonas con mayor actividad. El mapa debe ser interactivo (tooltip al pasar), adaptable al tema oscuro/claro, y cargado sin dependencias externas de CDN.

---

## Arquitectura

### Antes (Leaflet heatmap)
- Leaflet + leaflet.heat cargados vía CDN
- Puntos de calor sobre teselas CartoDB
- Ciudades agrupadas (muchas no tenían coordenadas)
- Problemas: todos los puntos se veían del mismo color

### Ahora (SVG nativo)
- SVG de Colombia inyectado dinámicamente vía JavaScript
- Cada `<path>` (departamento) se colorea según intensidad
- CSS variables para colores → actualiza automáticamente con el tema
- Sin CDN externo

---

## Campos en la API: `leads_geocoded`

### Endpoint
`GET /api/crm/tenants/{slug}/analytics/?days=&source=`

### Estructura del campo
```json
"leads_geocoded": [
  {
    "latitud": 4.8167,
    "longitud": -75.7000,
    "departamento": "Risaralda",
    "total": 7,
    "won": 3,
    "lost": 1,
    "intensidad": 1.0,
    "intensidad_won": 0.85
  }
]
```

### Lógica de cálculo (backend, views.py)

1. Se carga `departamentos_colombia.csv` una vez por request (coordenadas del centro de cada departamento).
2. Se agrupan leads por `contact.city.department.name`.
3. `intensidad = min(1.0, (total / max_total) ** 0.7)` — donde `max_total` es el conteo más alto del periodo.
4. Se retorna ordenado por `total` descendente.

**Nota:** Los leads ahora se agrupan por **departamento**, no por ciudad. Esto evita el problema de ciudades sin coordenadas y да una vista más estratégica (regional en lugar de granular por ciudad).

## Leyenda y selector de métrica

El mapa incluye una leyenda con selector de métrica:

- **Total Leads:** coloreado según `(total / max_total)^0.7`
- **Cerrados Ganados:** coloreado según `(won / max_won)^0.7`
- **Tasa Conversión:** coloreado según `won/total` normalizado

El selector se encuentra debajo del mapa. Al cambiar la opción, el mapa se re-renderiza con los colores correspondientes. La leyenda muestra los 3 niveles: Alta (rojo), Media (amarillo), Baja (verde).

El SVG usa IDs como `CO-ANT` (Antioquia), `CO-RIS` (Risaralda), etc. El JavaScript tiene un mapa de traducción:

```javascript
var deptNameToSVGId = {
    'antioquia': 'ANT',
    'risaralda': 'RIS',
    'córdoba': 'COR',
    'bogotá d.c.': 'DC',
    // ... los 33 departamentos
};
```

Si el nombre del departamento en la API coincide con la clave del mapa, se busca el ID SVG correspondiente y se colorea ese `<path>`.

## Cómo probar manualmente

1. **Poblar leads de prueba:**
   ```bash
   python manage.py seed_dynamic
   ```
   Genera leads distribuidos en varios departamentos.

2. **Abrir el dashboard de analíticas:**
   ```
   http://localhost:8000/crm/codensolar/analytics/
   ```

3. **Verificar el mapa:**
   - Los departamentos con leads se colorean (verde → rojo) según intensidad.
   - Al pasar el mouse sobre un departamento aparece tooltip con nombre + total de leads.
   - Al cambiar tema (oscuro/claro), los colores se actualizan automáticamente.
   - Departamentos sin datos aparecen en gris.

4. **Cambiar rango de tiempo:**
   - Semana / Mes / Trimestre / Año actualiza los colores del mapa.

## Limitaciones conocidas

- **Nombres deben coincidir:** El nombre del departamento en la API (`departamento`) debe tener su entrada en `deptNameToSVGId`. Departamentos con nombres distintos no se colorearán.
- **Sin zoom/pan:** El SVG es estático (no interactivo como Leaflet). Para mapas interactivos más adelante, considerar Mapsvg.js o Leaflet con SVG overlay.
- **Rango de intensidad:** Si todos los departamentos tienen counts bajos, el mapa será mayormente gris.

## Responsive (mobile)

El mapa ocupa todo el ancho del contenedor y la tabla se apila debajo automáticamente gracias al grid CSS (`charts-grid-2`). En pantallas pequeñas (<768px) el layout es vertical.
